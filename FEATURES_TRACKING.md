# Suivi Détaillé des Fonctionnalités

Ce document retrace, avec la plus grande granularité possible, l'ensemble des fonctionnalités implémentées dans le projet, leur fonctionnement et les composants logiciels impliqués.

| Fonctionnalité | Description du Fonctionnement | Composants Logiciels Impliqués |
| :--- | :--- | :--- |
| **Architecture MVC** | L'application est structurée en 3 pôles : Modèle (données), Vue (interface), Contrôleur (logique). `main.py` initialise et connecte ces 3 parties pour une séparation claire des responsabilités. | `main.py`, `model.py`, `controller.py`, `View/window.py` |
| **Thème Visuel Global** | Une feuille de style (CSS) est appliquée à toute l'application pour garantir un aspect cohérent : fond blanc cassé, texte noir, police Verdana, et bordures fines. | `main.py` (`app.setStyleSheet(...)`) |
| **Icônes SVG Personnalisées** | Les icônes de la barre d'outils sont définies en code SVG, ce qui garantit une haute qualité visuelle à n'importe quelle taille. Une fonction les convertit en `QIcon` utilisables par l'interface. | `resources/icons.py`, `View/window.py` |
| **Barre d'outils avec modes** | La barre d'outils contient des boutons pour activer des modes de création (Localité, Transition). Un `QActionGroup` garantit qu'un seul mode peut être actif à la fois. | `View/window.py` (`QToolBar`, `QActionGroup`) |
| **Bouton de mode "cochable"** | Lorsqu'un mode de création est activé (ex: "Nouvelle Localité"), le bouton correspondant reste enfoncé et grisé. Re-cliquer dessus désactive le mode et le bouton reprend son apparence normale. | `View/window.py` (`btn_add.setCheckable(True)`), `main.py` (`QToolButton:checked`), `controller.py` (`handle_add_location(checked=...)`) |
| **Changement du curseur** | Quand un mode de création est actif, le curseur de la souris se transforme en croix (+) sur la zone de dessin, indiquant à l'utilisateur qu'une action de création est attendue. | `View/canvas.py` (`set_creation_mode`), `controller.py` |
| **Création d'une Localité (Nœud)** | 1. Le `Controller` active le mode "location". <br> 2. L'utilisateur clique sur le `Canvas`. <br> 3. Le `Canvas` envoie les coordonnées au `Controller`. <br> 4. Le `Controller` demande au `Model` de créer une nouvelle localité dans ses données. <br> 5. Le `Controller` ordonne au `Canvas` de dessiner le nœud visuel. | `controller.py` (`handle_canvas_click`), `model.py` (`add_location`), `View/canvas.py` (`mousePressEvent`, `draw_node`), `View/items.py` (`NodeItem`) |
| **Nommage automatique des localités** | Chaque nouvelle localité se voit attribuer un identifiant unique et séquentiel, commençant par "l0", puis "l1", "l2", etc. Le `Model` gère un compteur interne pour cette tâche. | `model.py` (`loc_counter`, `add_location`) |
| **Affichage du nom de la localité** | L'identifiant de la localité (ex: "l0") est affiché au centre du cercle. La police utilisée est "Palatino", en italique, taille 12. | `View/items.py` (`QGraphicsTextItem`, `QFont`) |
| **Identification de l'état initial** | La toute première localité créée ("l0") est automatiquement désignée comme l'état initial de l'automate. Le `Model` stocke cette information dans son dictionnaire de données. | `model.py` (`data["init"]`) |
| **Représentation visuelle de l'état initial** | L'état initial est visuellement distinct des autres : il est dessiné avec une double bordure (un second cercle, plus petit, est dessiné à l'intérieur du premier). | `View/items.py` (test sur `is_initial` pour dessiner un `QGraphicsEllipseItem` enfant) |
| **Création d'une Transition (Flèche)** | 1. Le mode "transition" est activé. <br> 2. L'utilisateur clique sur une première localité (Source) mémorisée par le Contrôleur. <br> 3. L'utilisateur clique sur une seconde localité (Cible). <br> 4. Une flèche est dessinée dynamiquement du centre du premier au bord du second, enregistrée dans le Modèle et la Vue. | `View/canvas.py` (`node_clicked`), `controller.py` (`handle_node_click`), `View/items.py` (`TransitionItem`, calcul géométrique flèche), `model.py` (`add_transition`) |
| **Déplacement dynamique des nœuds et transitions** | Les nœuds peuvent être déplacés à la souris. Grâce à l'événement `itemChange` activé par `ItemSendsGeometryChanges`, chaque nœud notifie ses transitions connectées de recalculer leur position géométrique en temps réel pendant le déplacement. | `View/items.py` (`ItemIsMovable`, `itemChange`, `TransitionItem.update_position`) |
| **Esquive Dynamique des Transitions (Courbure)** | Les transitions se courbent automatiquement pour éviter les collisions avec d'autres nœuds présents sur leur trajectoire, ou s'il existe une transition réciproque (aller-retour). Le tracé devient une courbe de Bézier (`QGraphicsPathItem`) calculée en temps réel au déplacement d'un nœud. | `View/items.py` (`TransitionItem.update_position`, `QPainterPath`) |
| **Raffinements Graphiques des Transitions** | L'épaisseur des flèches a été réduite à 1px (identique aux bordures des nœuds) et les pointes de flèches sont dessinées sous forme de triangles pleins via `drawPolygon`. | `View/items.py` (`TransitionItem`, `paint`) |
| **Création de Transitions Multi-segments (Clous)** | L'utilisateur peut cliquer sur le canevas pendant le tracé d'une transition pour poser des "clous" (`NailItem`). La flèche passe du Drag&Drop à un modèle Click-to-Click (ligne pleine au lieu de pointillée). Un correctif de profondeur ignore le tracé en cours pour détecter correctement la localité cible finale. Les clous sont déplaçables et mettent à jour le tracé en temps réel. Le clic droit annule l'action. | `View/canvas.py` (`mousePressEvent`, `mouseMoveEvent`), `View/items.py` (`NailItem`, `TransitionItem`) |
| **Déclarations Globales (Actions & Horloges)** | Ajout de fenêtres volantes (`QDialog`) pour la saisie d'actions et d'horloges. Interface stylisée (fond clair `#FAFAFA`, décalage vertical de -200px) et ergonomie optimisée (validation via `Entrée`, champ vidé automatiquement avec maintien du focus). | `View/window.py` (`DeclarationDialog`, `show_action_dialog`, `show_clock_dialog`), `controller.py` |
| **Filtrage Anti-doublons (Modèle)** | Le `Model` s'enrichit de listes pour stocker les actions et horloges. Il applique une règle métier qui ignore silencieusement les nouvelles soumissions si elles existent déjà. | `model.py` (`add_action`, `add_clock`) |
| **Mode Débogage du Modèle** | Ajout d'une action dans le menu Fichier avec le raccourci `Ctrl+D` (ou `Cmd+D`) permettant d'imprimer l'état complet des attributs de l'instance du `Model` dans la console via le module `pprint`. | `View/window.py` (`_setup_menubar`), `controller.py` (`debug_print_model_instance`) |
| **Édition Multi-Invariants (Nœuds)** | Le panneau latéral permet d'ajouter, lister et supprimer plusieurs invariants (horloge, opérateur, valeur) pour une même localité. La sélection d'une horloge existante met à jour l'invariant pour éviter les doublons contradictoires. | `View/properties_dock.py`, `controller.py`, `model.py` |
| **Menu Contextuel de Suppression** | Un clic droit sur un nœud ou une flèche affiche un menu flottant (`QMenu`) permettant sa suppression. Design plat avec alerte visuelle rouge. | `View/items.py` (`contextMenuEvent`) |
| **Suppression en Cascade** | La suppression d'une localité déclenche via le `Controller` la suppression automatique de toutes les transitions connectées (source ou cible) dans le `Model` et la `View`, assurant la cohérence des données. | `controller.py` (`handle_delete_node`), `model.py`, `View/canvas.py` |
| **Refonte Visuelle (Flat Design QSS)** | Centralisation du style global dans `main.py` pour un rendu minimaliste et moderne : listes déroulantes (QComboBox) plates, champs de texte interactifs (focus bleu électrique) et suppression des bordures pointillées natives de Qt. | `main.py` (`setStyleSheet`), `View/properties_dock.py` |
