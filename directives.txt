Contexte : Dans mon application PySide6 (architecture MVC), je gère un éditeur d'automates temporisés. Je souhaite implémenter une validation anti-doublon logique lors de l'ajout d'une contrainte (invariant ou garde) dans le contrôleur.

Objectif : Si l'utilisateur tente d'ajouter une contrainte qui est mathématiquement et logiquement équivalente à une contrainte déjà présente dans la liste, le système doit l'ignorer et ne pas l'ajouter.

Exemple de la règle visée : > Ajouter x <= y (offset 0) alors que y >= x (offset 0) est déjà présent doit être bloqué.

Rappel de la structure d'une contrainte en dictionnaire :
{'clock': 'x', 'operator': '<=', 'type': 'clock', 'value': 'y', 'offset': 0}

Spécifications de la validation (À implémenter) :

Création d'une fonction d'équivalence :

Écrire une méthode utilitaire (dans le Modèle ou le Contrôleur) par exemple is_constraint_equivalent(new_c, existing_c).

Cette fonction renvoie True si :

Les deux dictionnaires sont strictement identiques.

OU si c'est une comparaison entre deux horloges (type == 'clock') et que la relation inversée est respectée :

new_c['clock'] == existing_c['value']

new_c['value'] == existing_c['clock']

L'opérateur est l'inverse exact : (<= devient >=, >= devient <=, == reste ==)

L'offset est inversé : new_c['offset'] == -existing_c['offset']

Intégration dans l'ajout (Contrôleur) :

Dans la méthode qui valide le formulaire d'ajout d'une contrainte, juste avant de l'ajouter à la liste interne (self.current_constraints), faire une boucle sur les contraintes déjà présentes.

Si is_constraint_equivalent renvoie True pour l'une d'elles, interrompre l'ajout (optionnel : afficher un petit message dans la console indiquant que la contrainte existe déjà).

Travail demandé :
Génère le code Python de la fonction is_constraint_equivalent et montre-moi comment l'intégrer proprement dans ma méthode d'ajout du contrôleur avec une boucle de vérification.
